2.缺页

缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

- 请问哪些异常可能是缺页导致的？

Load access fault；Store access fault；Load page fault；Store page fault。



- 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。

Trap相关: 缺页引发异常，切换至内核态，`sstatus` 记录trap发生前的特权级，`sepc` 记录导致trap发生的指令地址，`scause` 描述trap的原因(page fault)，`stval` 给出trap附加信息(访问的地址)，`stvec` 控制trap处理代码的入口地址



缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

- 这样做有哪些好处？

(1) 节省内存资源，在实际使用之前，不需要加载进内存

(2) 减少 I/O 操作，加载不使用的代码的 I/O 操作是不必要的

(3) 提高响应速度，不需要等程序的所有代码加载进内存就可以运行程序

(4) 减少页面置换开销，如果所有程序都将全部代码加载进内存，很容易导致内存不足而频繁发生页面置换



其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

- 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

一个页表项映射4KB，一共需要映射 10*2^30B内存

需要 10*2^30B / 2^12B = 10 * 2^18 个页表项

一个页表项为 8B，一共需要 10 * 2^18 * 8 = 20 * 2^20 B = 20MB 存储

需要 10*2^18 * 8 / 2^12 = 5 * 2^10 页 三级页表 存储

一页二级页表存储 2^12B / 2^3B = 2^9 个二级页表项，即映射2^9页 三级页表

5 * 2^10 / 2^9 = 10，即 5 * 2^10 页 三级页表需要10页二级页表映射

所以一共需要 1页一级页表，10页二级页表，5*2^10页三级页表

即: (5 * 2^10 + 11) * 2^12B = 20MB + 44KB

所以处理 10G 连续的内存页面，对应的 SV39 页表大致占用20MB内存



- 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

用户请求内存时，修改对应空闲页面的pte标志位，可以使用保留的标志位标记为lazy，但不将valid位置1；

用户真正使用相应的页面时，会触发page fault进入trap处理函数；此时可以检查页面对应的pte的标志位，如果是lazy导致的page fault，就实际分配页面，并将pte的valid位置1。



缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。

- 此时页面失效如何表现在页表项(PTE)上？

有效位V为0，表示该页面不在内存



3.双页表与单页表

为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说， 用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 [KPTI](https://en.wikipedia.org/wiki/Kernel_page-table_isolation) )

- 在单页表情况下，如何更换页表？

用户线程和对应的内核线程切换时不需要更换页表；

切换不同的用户线程时才需要更换页表，修改satp寄存器即可更换页表。因为更换页表会导致映射也被修改，需要保证修改satp寄存器后是平滑的。现将修改satp寄存器这段汇编代码记为跳板指令序列，将跳板指令序列独立写在一个物理页中，将所有用户线程的页表的某一段固定的虚拟地址映射到该物理页，即可保证切换页表时是平滑的。



- 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

设置PTE的U位，使用PTE的访问设置控制用户态无法访问内核页面



- 单页表有何优势？（回答合理即可）

内核和用户的逻辑段放在同一地址空间，所以Trap 的时候不需要切换地址空间，更改特权级直接在当前地址空间访问内核页面即可，能够避免机制空间切换的开销，也更易于实现



- 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？

Trap时需要访问内核代码，内核代码位于内核的地址空间，所以需要更换页表，切换任务的时候，不同任务的页表也是不同的，也需要更换页表。

单页表操作系统每个的应用都有一个地址空间，分为内核和应用，Trap时不需要更换页表，在任务切换时更换页表
